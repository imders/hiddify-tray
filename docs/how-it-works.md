# Как это устроено

Заметки о внутренностях Hiddify, собранные при разработке. Может пригодиться тем,
кто хочет управлять им из своих скриптов.

## Проблема

Hiddify запускается, но остаётся отключённым — ядро поднимается только по нажатию
круглой кнопки на главном экране. Для автоматизации нужен способ нажать её программно.

## Что не сработало

**Эмуляция клика.** Окно Hiddify нарисовано на Flutter, и обычные способы не проходят:
в дереве нет доступных контролов, кликать можно только по координатам. Координаты нашлись
(центр кнопки — примерно `0.497 × 0.511` от размера окна; в подключённом состоянии кнопка
смещается вверх, потому что под ней появляются строки статуса), но **Flutter не принимает
синтетический ввод**: три клика точно в центр кнопки не дали ничего. Подход выброшен.

**Clash API.** Hiddify поднимает совместимый с Clash API на отдельном порту, и он полезен —
через него читаются версия ядра, счётчики трафика и активный маршрут. Но включением
и выключением туннеля он не управляет: это уровень ядра, а не маршрутизации.

**`HiddifyCli.exe`.** Лежит рядом с приложением, но запускает собственный экземпляр ядра
и конфликтует с GUI за TUN-адаптер.

**URL-схема `hiddify://`.** Зарегистрирована, но умеет только импорт профиля.

## Что сработало: gRPC

`hiddify-core.dll` содержит gRPC-сервер. Имена методов извлекаются прямо из бинарника:

```bash
grep -aoE '/[A-Za-z][A-Za-z0-9_.]*\.[A-Za-z][A-Za-z0-9_]*/[A-Za-z][A-Za-z0-9_]*' hiddify-core.dll | sort -u
```

Находится сервис `hcore.Core`:

| Метод | Назначение |
|---|---|
| `/hcore.Core/Start` | Поднять ядро |
| `/hcore.Core/Stop` | Погасить ядро |
| `/hcore.Core/Restart` | Перезапустить |
| `/hcore.Core/GetSystemInfo` | Сведения о системе и активном профиле |
| `/hcore.Core/SelectOutbound` | Выбрать исходящее соединение |
| `/hcore.Core/ChangeHiddifySettings` | Изменить настройки |

Сервер слушает `127.0.0.1:17078` (порт стабилен между перезапусками, но лучше уметь искать).

`Start`, `Stop` и `GetSystemInfo` принимают **пустое сообщение** — схема protobuf не нужна,
достаточно отправить нулевую длину. Именно поэтому обёртка обходится без `grpcio` и `grpcurl`.

## gRPC вручную

gRPC — это HTTP/2 плюс простой формат кадра:

```
[1 байт: флаг сжатия][4 байта: длина, big-endian][protobuf-сообщение]
```

Для пустого сообщения тело запроса — ровно пять нулевых байт. Требования:

- метод `POST`, путь — имя сервиса и метода;
- заголовок `content-type: application/grpc`;
- **HTTP/2 без TLS** (h2c) — отсюда требование PowerShell 7: в 5.1 такого нет;
- результат вызова лежит не в статусе HTTP, а в трейлере `grpc-status` (`0` — успех).

Ответ `Start` при уже поднятом ядре — `instance already started`, что удобно:
повторный вызов безопасен.

## Определение состояния

Факт работы ядра проверяется по Clash API: если он отвечает — ядро поднято.
Здесь есть ловушка: **секрет Clash API генерируется заново при каждом запуске ядра**.
Прочитать его один раз при старте недостаточно — после первого же перезапуска VPN
значение протухнет, и статус залипнет. Секрет нужно перечитывать из
`%APPDATA%\Hiddify\hiddify\data\current-config.json`, когда процесс жив, а API молчит.

## Мелочи, которые стоили времени

**Обработчик горячей клавиши не должен ходить в сеть.** Первая версия делала HTTP-запрос
внутри обработчика, чтобы узнать текущее состояние, — нажатия терялись. Решение: опираться
на состояние, уже полученное фоновым опросом.

**Иконка трея обязана быть многоразмерной.** Windows рисует в трее 16×16 (20 и 24 при
масштабе 125 и 150 %). Если в `.ico` лежит только 32×32, система ужимает его сама, и иконка
выглядит мыльной. Все размеры нужно отрисовать отдельно — этим занят `tools/build-icons.ps1`.

**Состояния должны различаться формой, а не только цветом.** На 16 пикселях оттенок читается
плохо, да и дальтонизм никто не отменял. Здесь: сплошной щит, контур с точками, перечёркнутый контур.

## DNS и медленное подключение

Если Hiddify настроен на DoH по доменному имени, его адрес нужно сначала разрезолвить —
обычно через `dns-direct`, то есть **UDP на порт 53**. У части провайдеров этот порт
блокируется или подменяется, и резолв уходит в таймауты по 10 секунд, а с ним и всё подключение.

Проверить можно в `current-config.json`: у сервера `dns-remote` смотрим поля `server`
и `domain_resolver`. Если `server` — доменное имя, а рядом стоит `domain_resolver`, значит
цепочка есть. DoH по IP-литералу (`https://1.1.1.1/dns-query`) убирает её совсем:
`domain_resolver` из конфига пропадает, резолвить нечего.
